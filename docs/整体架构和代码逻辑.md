# 整体架构和代码逻辑

> 本文档描述 ClawParty 项目各目录/模块的职责划分、核心数据流和在整体系统中的角色。旨在帮助开发者（及 AI Coding Agent）快速理解系统全貌，无需每次都从头阅读源码。

---

## 一、架构总览

ClawParty 是一个**多进程协作的 AI 代理平台**，核心思想是：

- **一个网络入口进程**（`tui/clawparty`）负责对外提供 HTTPS/WebSocket 服务、用户认证、静态网页，并把请求代理到内部各服务。
- **多个 AI Agent 进程**（`zeroclaw`）各自独立运行，每个 agent 占用一个端口、一个工作目录（通常位于 `~/.clawparty/agents/<name>/`）。
- **一个可选的分布式网络层**（`ztm`）提供 mesh 组网、P2P 穿透、文件同步等能力，由 `tui/clawparty` 按需启动。

整体进程关系：

```
用户浏览器 / Desktop App
        │
        ▼
┌─────────────────────────────┐
│  tui/clawparty (Rust)       │  ← 网络入口、HTTPS代理、认证、内嵌Web GUI
│  - 443/80 端口对外服务      │
│  - 代理 /api/* 到 ztm:6789  │
│  - 代理 /api/zeroclaw/* 到  │
│    各 zeroclaw 进程端口     │
└─────────────────────────────┘
        │
   ┌────┴─────────────────────┐
   │                          │
   ▼                          ▼
zeroclaw (Rust)           ztm agent (PipyJS)
- 0#Agent @ 42617         - 127.0.0.1:6789
- 其他 agents @ 各自端口  - mesh / P2P / 文件系统
- 提供 AI chat / tools    - 提供 mesh chats / endpoints
- WebSocket 流式响应      - 分布式网络
```

## 二、五大核心模块

### 1. tui — ClawParty 主程序（Rust）

**目录**：`tui/`

**角色**：整个系统的**门面和进程管家**。它是唯一对外暴露端口的进程，所有 HTTP/HTTPS/WebSocket 流量都先到达这里，再被路由到后端。

**关键能力**：

| 能力 | 说明 |
|------|------|
| 静态文件服务 | 内嵌 `chat-gui` 编译产物（`tui/gui/`），提供 Vue SPA |
| HTTPS 反向代理 | 443/80 端口，自签名证书，HTTP→HTTPS 重定向 |
| 用户认证 | `/api/login` 走本地 `clawparty.db`（SQLite），其他 `/api/*` 需 Bearer Token |
| 路由分发 | `/api/zeroclaw/*` → zeroclaw 端口；其余 `/api/*` → ztm agent (127.0.0.1:6789)；非 API → 静态文件 |
| WebSocket 代理 | WS 连接直接桥接到 zeroclaw 进程的 WebSocket，不做修改 |
| 本地 API 实现 | Task、Wiki、Agent 管理、GroupChat、Kanban、Radar、WebShare 等路由由 Rust 直接处理（不转发到 ztm） |
| 进程管理 | 启动/重启/看门狗 ZeroClaw Daemon 和 ZTM Agent 进程 |

**关键文件**：

- `src/main.rs` — 入口：命令行解析、首次运行初始化、启动 ZeroClaw、启动 ZTM Agent、TUI 事件循环
- `src/app.rs` — 全局状态 `AppState`：sidebar 数据、消息、会话、scroll 状态、各面板
- `src/proxy.rs` — HTTPS 代理核心：TLS、HTTP 路由、WS 桥接、认证中间件、本地 API 路由表
- `src/static_files.rs` — 使用 `rust_embed` 内嵌 `tui/gui/` 的静态文件，SPA fallback 到 `index.html`
- `src/agent.rs` — `AgentManager`：封装 `ztm` 进程的启动、日志采集、重启、停止（`pipy run agent …`）
- `src/zeroclaw.rs` — `ZeroClawDaemon`：封装 `zeroclaw daemon …` 进程的启动、健康检查、会话拉取
- `src/agents.rs` — 本地 Agent（zAgent）的 CRUD、启动/停止、文件系统同步、工作区初始化
- `src/api.rs` — `ApiClient`：HTTP 客户端，封装对 ztm agent API 和 zeroclaw API 的调用
- `src/tasks.rs` / `src/wiki.rs` / `src/radar.rs` / `src/webshare.rs` — 本地独立模块，直接操作文件系统或 `clawparty.db`

**运行模式**：
- **TUI 模式**（默认）：终端交互界面，适合本地调试
- **Service 模式**（`--service` / `-s`）：后台服务，无 TUI，提供 HTTPS + WebSocket + 静态网页
- **ZeroClaw-only 模式**（`--zeroclaw-only`）：不启动 ZTM Agent，仅提供 zeroclaw 相关功能

### 2. zeroclaw — Agent 执行引擎（Rust）

**目录**：`zeroclaw/`

**角色**：**真正的 AI Agent 运行时**。每个 zeroclaw 进程是一个独立的 AI 助手实例，拥有自己的工作目录、配置文件、记忆、工具、渠道。`tui/clawparty` 负责管理它的生命周期（启动、停止、分配端口）。

**关键能力**：

| 能力 | 说明 |
|------|------|
| Gateway | HTTP/WebSocket 服务器，接收外部请求，流式返回 AI 响应 |
| AI Provider 抽象 | 支持 OpenAI、Anthropic、OpenRouter 等，统一 trait |
| Tool 系统 | shell、browser、file、memory 等工具调用 |
| Channel 系统 | Telegram、Discord、Slack、Matrix、邮件等 30+ 消息渠道 |
| Memory 后端 | SQLite / Markdown / Lucid / Vector Merge |
| Cron / Scheduler | 定时任务、 recurring 任务 |
| SOP / Skills | 标准操作流程、用户自定义技能 |
| Hardware | STM32、Raspberry Pi GPIO、ESP32 等外设支持 |
| Security | OTP、estop（紧急停止）、sandbox |

**进程启动方式**（由 `tui` 或用户 CLI 触发）：

```bash
zeroclaw daemon -p <port>          # tui 启动 agent 时用的命令
zeroclaw gateway start              # 手动启动 gateway
zeroclaw agent                      # 交互式 CLI 聊天
zeroclaw acp                        # JSON-RPC over stdio（IDE 集成）
```

**关键文件/目录**：

- `src/main.rs` — CLI 入口，命令路由（`daemon`、`gateway`、`agent`、`acp` 等）
- `src/gateway/mod.rs` — re-export `zeroclaw-gateway` crate
- `src/service/mod.rs` — OS 服务生命周期（systemd/launchd）
- `crates/zeroclaw-api/` — 公共 trait：Provider、Channel、Tool、Memory、Observer、Peripheral
- `crates/zeroclaw-runtime/` — Agent 主循环、安全、Cron、SOP、技能、可观测性
- `crates/zeroclaw-gateway/` — HTTP/WebSocket gateway 实现
- `crates/zeroclaw-channels/` — 30+ 消息渠道集成
- `crates/zeroclaw-tools/` — 工具执行层
- `crates/zeroclaw-memory/` — 记忆后端
- `crates/zeroclaw-providers/` — 模型提供商封装
- `crates/zeroclaw-config/` — 配置 schema、加载与合并
- `crates/zeroclaw-hardware/` — USB 发现、外设、串口

**与 tui 的关系**：
- `tui` 是“操作系统层”，管理多个 zeroclaw 进程
- `zeroclaw` 是“应用层”，每个进程专注于一个 AI Agent 实例
- 用户通过浏览器/chat-gui 发送消息 → tui proxy → 对应 zeroclaw 进程的 WebSocket/HTTP

### 3. ztm — 分布式网络层（PipyJS + C++ 引擎）

**目录**：`agent/`、`hub/`、`ca/`、`pipy/`、`cli/`

**角色**：提供**mesh 网络组网**能力。Agent 加入一个 mesh 后，可以和 mesh 中的其他 endpoint（节点）建立加密隧道，共享应用（apps）、文件系统、聊天、代理隧道等。Pipy 是运行这些 PipyJS 脚本的底层 C++ 引擎。

#### 3.1 `pipy/` — Pipy 运行时引擎（C++）

- 一个可编程的网络代理/脚本引擎，内置 HTTP、TLS、WebSocket、Crypto、SQLite、OS API 等
- 编译产物通常是 `bin/ztm`（因为 `ztm` 脚本以 Pipy 为 shebang 运行）
- 有自己的 JavaScript 方言（PipyJS），**不支持**部分标准 JS API（见 AGENTS.md 中的 Pipy 运行时约定）

#### 3.2 `agent/` — ZTM Agent（PipyJS）⭐ 最重要

- 入口：`agent/main.js`
- 被 `tui` 以 `pipy run agent --listen 127.0.0.1:6789 --data ~/.clawparty --api-token …` 启动
- 内部路由表（`routes`）非常庞大，覆盖：
  - `/api/meshes/*` — mesh 管理（加入/离开/配置）
  - `/api/meshes/{mesh}/endpoints/*` — endpoint 管理
  - `/api/meshes/{mesh}/hubs/*` — hub 管理
  - `/api/meshes/{mesh}/apps/*` — 应用生命周期
  - `/api/meshes/{mesh}/files/*` — 分布式文件系统
  - `/api/chats/*` / `/api/peers/*` / `/api/groups/*` — mesh 聊天
  - `/api/agents/*` — 本地 AI Agent 状态/创建/删除/启停（注意：这是 ztm 的 agent API，管理的是 zeroclaw agent 的元数据）
  - `/api/zeroclaw/*` — 透传到 zeroclaw gateway
  - `/api/tasks/*` / `/api/kanban/*` / `/api/groupchats/*` — 任务/看板/本地群聊
  - `/api/global-config` / `/api/webshare/*` — 全局配置/WebShare
- 内部调用 `openclaw` CLI 来获取/操作本地 agent 信息
- `agent/apps/ztm/chat/main.js` — chat app 内部逻辑，包含 `openclaw` 命令队列（串行执行防止并发超时）
- `agent/apps/ztm/*/` — 其他内置 app：proxy、cloud、tunnel、payment、users

#### 3.3 `hub/` — ZTM Hub（PipyJS）

- 入口：`hub/main.js`
- 提供中心化的 endpoint 注册、证书签发、文件系统同步、ACL、邀请码注册
- 支持集群模式（`cluster.js`）
- 包含开放的注册 API（`POST /invite`），用于新 endpoint 自助获取证书

#### 3.4 `ca/` — 简易 CA 服务（PipyJS）

- 入口：`ca/main.js`
- 示例性质的证书颁发服务，`hub/` 在生产中通常内置了自己的 CA 逻辑

#### 3.5 `cli/` — ZTM CLI（PipyJS）

- 入口：`cli/main.js`
- 命令行工具，用于与 `agent/` 交互：`ztm start`、`ztm stop`、`ztm get meshes`、`ztm run chat` 等
- 也包含一些 openclaw 相关的命令封装

**与 tui 的关系**：
- `tui` 启动 `agent/main.js`（ZTM Agent），提供 mesh 能力
- 如果 `--zeroclaw-only`，则不启动 ZTM Agent，所有功能仅依赖 zeroclaw
- ZTM Agent 不是 tui 的核心依赖，是**可选增强**（P2P、文件同步、跨节点聊天）

### 4. desktop — 独立 macOS GUI（Swift + SwiftUI）

**目录**：`desktop/ClawPartyDesktop/`

**角色**：一个**独立的 macOS 状态栏应用**，用于图形化管理 ClawParty。它可以启动/停止 `tui/clawparty` 进程，查看日志，配置 LLM，管理 agent。

**关键文件**：

- `ClawPartyDesktopApp.swift` — App 入口，NSApplicationDelegate，管理主窗口和 LLM 配置窗口
- `StatusBarController.swift` — 状态栏图标、菜单
- `MainPanelView.swift` / `ContentView.swift` — 主界面 SwiftUI Views
- `ProcessManager.swift` — 核心逻辑：检测现有 clawparty 进程、启动（`-s` service 模式）、停止、日志采集
- `ConfigManager.swift` — 配置读写
- `LLMConfigView.swift` — LLM 参数配置界面

**与 tui 的关系**：
- Desktop App 是 tui 的“包装器”，它并不替代 tui 的任何功能
- 它通过 `ProcessManager` 启动 `bin/clawparty -s`，把 tui 当作一个后台服务进程管理
- 它也可以检测到由终端手动启动的 clawparty 进程

### 5. chat-gui — Web UI（Vue 3 + Vite）

**目录**：`chat-gui/`

**角色**：用户-facing 的**网页聊天界面**。编译后被嵌入 `tui/gui/` 目录，由 `tui/clawparty` 的静态文件服务直接提供。

**关键能力**：

| 能力 | 说明 |
|------|------|
| 登录 | `/api/login` 认证，Token 存 localStorage |
| Mesh 聊天 | 与 ztm mesh 中的 peer/endpoint 聊天 |
| ZeroClaw 会话 | 与 zeroclaw agent（通过 WebSocket）流式交互 |
| zAgent 管理 | 创建、删除、启动、停止 zeroclaw agent |
| 本地群聊 | ZeroClaw agent 之间的本地群组 |
| 任务管理 | 解析 AI 响应中的 `<task>` 标签，自动创建/更新任务 |
| 模板市场 | 安装本地/共享 agent 模板 |
| 移动端适配 | 响应式布局，移动端独立视图 |

**关键文件**：

- `src/App.vue` — 根组件，管理全局状态：mesh、chats、agents、zeroclaw sessions、zAgents、group chats
- `src/components/ChatMain.vue` — 聊天主面板（消息列表、输入框、工具栏）
- `src/components/ChatSidebar.vue` — 侧边栏（ZeroClaw Sessions、zAgents、Mesh Chats、Group Chats）
- `src/components/MessageInput.vue` — 消息输入、图片/文件发送、模板选择
- `src/services/chatService.js` — 封装所有 API 调用：mesh、chat、openclaw、zeroclaw、zagent、groupchat、task
- `src/services/wsService.js` — ZeroClaw WebSocket 客户端封装，支持重连、流式消息处理
- `src/services/wikiService.js` — Wiki 相关 API
- `src/services/radarService.js` — Radar 相关 API
- `src/services/ShellService.js` — 本地 Shell 命令（Tauri 环境）

**与 tui 的关系**：
- `chat-gui` 的构建产物（`npm run build`）输出到 `../tui/gui/`
- `tui/src/static_files.rs` 使用 `rust_embed` 把 `tui/gui/` 打包进二进制
- `tui` 的 HTTPS proxy 把所有非 API 请求都 fallback 到这个 SPA
- `chat-gui` 的所有 API 请求都发给 `tui` 的 HTTPS 入口，由 `tui` 的 proxy 决定是本地处理还是转发到 ztm/zeroclaw

## 三、数据流示例

### 场景：用户在 Web UI 中与 zAgent 聊天

```
[Browser] ChatMain.vue → chatService.sendZAgentMessage(agentName, text)
    │
    ▼ POST /api/zeroclaw/sessions/{id}/chat  (HTTPS, Bearer Token)
[Tui Proxy] proxy.rs::resolve_http_backend()
    → 路径以 /api/zeroclaw/ 开头 → 代理到 localhost:{agentPort}/api/sessions/{id}/chat
    │
    ▼
[ZeroClaw Gateway] zeroclaw_gateway::run_gateway()
    → 调用 AI Provider → 流式返回 chunk
    │
    ▼ WebSocket (流式响应)
[Tui Proxy] proxy.rs::proxy_websocket()
    → 桥接 frontend WS ↔ backend WS (localhost:agentPort)
    │
    ▼
[Browser] wsService.js::ZeroClawWS
    → 解析 chunk/done/error 消息 → 更新 Vue reactive state → 渲染到 ChatMain
```

### 场景：用户创建一个 zAgent

```
[Browser] App.vue → zagentService.createAgent(config)
    │
    ▼ POST /api/agents
[Tui Proxy] proxy.rs::handle_request()
    → 路径 /api/agents → 本地 Rust 处理（agents.rs::create_agent）
    │
    ▼
[Tui] agents.rs
    → 在 ~/.clawparty/agents/<name>/ 创建工作目录
    → 生成 config.toml
    → 写入 clawparty.db
    → spawn zeroclaw daemon -p <port> --config-dir <dir>
    │
    ▼
[ZeroClaw] zeroclaw daemon
    → 读取 config.toml → 启动 Gateway → 监听分配端口
```

### 场景：Desktop App 启动 ClawParty

```
[macOS Desktop] ProcessManager.startClawParty()
    → spawn bin/clawparty -s
    │
    ▼
[Tui Service Mode]
    → 启动 ZeroClaw Daemon (0#Agent @ 42617)
    → 启动所有已注册 agents 的 zeroclaw 进程
    → 启动 ZTM Agent (@ 6789)（非 zeroclaw-only 模式）
    → 启动 HTTPS Proxy (@ 443)
    → 打开浏览器（--open）
```

## 五、关键约定（跨模块）

### 端口约定

| 服务 | 默认端口 | 说明 |
|------|---------|------|
| tui HTTPS proxy | 443 / 80 | 对外入口 |
| tui HTTP redirect | 80 | 仅 service 模式 |
| ZeroClaw Gateway (0#Agent) | 42617 | 主 agent，不可删除 |
| 其他 ZeroClaw agents | 动态分配 | 由 tui 在创建时分配，记录在 clawparty.db |
| ZTM Agent | 6789 | 本地 mesh agent |
| ZTM Hub | 8888 | 中心 hub |

### 数据库/存储

| 文件 | 所在目录 | 用途 |
|------|---------|------|
| `clawparty.db` | `~/.clawparty/` | tui 本地：agents、users、tasks、groupchats、kanban 等 |
| `ztm.db` | `~/.clawparty/` | ZTM Agent 本地：meshes、endpoints、chats、files ACL |
| `ztm-hub.db` | `~/.ztm/` | ZTM Hub：endpoints、users、invite codes、evictions |
| `config.toml` | `~/.clawparty/agents/<name>/` | 每个 zeroclaw agent 的配置 |
| `workspace/` | `~/.clawparty/agents/<name>/workspace/` | agent 的工作文件、wiki、radar、memory |

### 进程生命周期

- **tui** 退出时，会 `SIGKILL` 自己启动的 ZTM Agent 和 zeroclaw 子进程（通过 `Drop` + `kill(-pid, SIGKILL)`）
- Desktop App 退出时，会尝试优雅终止 clawparty（先 `SIGTERM`，3秒后 `SIGKILL`）
- 如果 zeroclaw 进程由 tui 启动，tui 是它们的父进程；如果由终端手动启动，tui 只能检测到已在运行，不会管理其生命周期

## 六、修改指南（按目标模块）

### 修改 HTTPS 路由或认证逻辑
→ 改 `tui/src/proxy.rs`（`handle_request` 路由表）

### 修改 Agent 创建/删除/启停逻辑
→ 改 `tui/src/agents.rs` + `tui/src/db.rs`

### 修改 ZeroClaw 启动参数或健康检查
→ 改 `tui/src/zeroclaw.rs` + `tui/src/main.rs`

### 修改 ZTM Agent 启动参数
→ 改 `tui/src/agent.rs` + `tui/src/main.rs`

### 修改 Web UI 聊天界面
→ 改 `chat-gui/src/components/*.vue` + `chat-gui/src/services/chatService.js`

### 修改 Web UI 与后端的数据交互
→ 改 `chat-gui/src/services/*.js`，同时确认 `tui/src/proxy.rs` 是否已有对应路由

### 修改 mesh 聊天/文件同步逻辑
→ 改 `agent/apps/ztm/chat/main.js` / `agent/main.js`

### 修改 AI Agent 的 Gateway/渠道/工具
→ 改 `zeroclaw/crates/zeroclaw-gateway/` / `zeroclaw-channels/` / `zeroclaw-tools/`

### 修改 Desktop App 的进程管理
→ 改 `desktop/ClawPartyDesktop/ProcessManager.swift`

### 修改构建流程
→ 改 `build/*.sh`，验证后更新本文件和 AGENTS.md
